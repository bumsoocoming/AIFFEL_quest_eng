# 역할 분리 멀티에이전트는 신도시 유물 발견 대응에서 제약을 더 잘 지키는가

> 1주 과제용 초안. 대괄호만 실제 숫자·사례로 바꾸고, 목차는 유지한다.

## 1. 동기

신도시 공사 중 매장유산이 나오면 시행 일정, 보존 의무, 조사 기간, 입주 지연이 한꺼번에 충돌한다. 하남 교산 같은 실제 지구에서 반복된 구도이나, 이 실험은 가상 청강 신도시를 쓴다. 질문은 모델을 더 많이 쓰는가가 아니라, **정보를 나눠 가진 역할극이 한 모델의 종합 대책보다 제약을 잘 지키는가**이다.

## 2. 방법

같은 브리핑, 같은 모델, 조건 두 개다. 단일 조건은 네 부서 내부 메모를 모두 읽은 정책보좌관이 합의문 JSON을 바로 쓴다. 멀티 조건은 시행사·문화재청·조사단·주민이 자기 비밀만 가진 채 1라운드 발언하고, 조정관이 말한 것만 합의문에 적는다. 각 3회, 정답 유형은 없다. 채점은 공사 즉시 중지, 정밀조사 8개월 하한, 국비 전액 확정 금지, 네 이해당사자 반영이다.

## 4. 사례 세 줄

1. **제약을 지킨 합의**: [폴더 이름. 무엇을 지켰는지 한 문장]
2. **허구 합의 또는 누락**: [누가 빠졌거나 어느 숫자가 비었는지]
3. **비밀이 전달되지 않음**: [8개월·위약·설문이 발언에 안 나와 합의문이 얇아진 경우]

## 5. 한계

가상 사례, 모델 하나, 각 3회, 토론 1라운드다. 자동 채점은 키워드라 오탐이 있다. 사람 채점을 기준으로 읽고 자동 점수는 보조로만 쓴다.

## 6. 결론

[표가 가리키는 쪽으로 한 문장. 예: 멀티는 금지선은 잘 말하지만 조사 기간을 합의문에 못 옮겼다 / 단일이 메모를 다 가지고 있어 제약을 더 안정적으로 지켰다.] 역할극 자체는 발표에 쓰되, 나눠 가진 숫자를 한 장으로 모으는 장치가 없으면 멀티를 쓸 이유가 약하다.
